The Grand Architecture

Two Worlds • Two Libraries

What is the missing link? Why are there two separate libraries? Here is the exact boundary between the JSON Specification World and the Native DOM World.

Tier 1: High-Level JSON-to-JSON Transformer

json-to-dom-renderers

The Business State & Spec Engine. Operates 100% in the JSON Specification World.

  • Input: Business Data (data.json), Column Schemas (columns.json), Display Configs (config.json), Theme Maps (classes.json).
  • State Management: Isolated stores (TableStore, FormStore, DataListStore).
  • Calculations: Multi-tier summary footers (aggregates like sum, evaluated formulas like amount * 0.18).
  • Autocomplete Profiling: Frequency counting with topN caps.
  • REST CRUD Adapter: createDataProvider for dynamic async fetching without auth coupling.
  • Output: Pure declarative JSON Element Specification Tree (inSpec). (Zero native DOM nodes created!)
// json-to-dom-renderers output:
{ tagName: "table", classList: [...], children: [...] }
Tier 2: Low-Level json-to-dom Repository

json-to-dom

The Native DOM Compiler. Crosses the boundary from the JSON World into the Physical DOM World.

  • Input: Pure JSON Element Specification Tree (inSpec).
  • Domain Knowledge: Zero! Knows nothing about tables, invoices, serial numbers, or search filters.
  • Compilation: Recursively executes native document.createElement, assigns classes, sets attributes, binds event listeners.
  • Efficiency: Direct native DOM instantiation with zero Virtual DOM overhead or diffing lag.
  • Output: Physical browser DOM element instances (HTMLTableElement, HTMLFormElement) or DocumentFragment.
  • Targeted Repainting: Works with surgical repainters to swap <tbody> and <tfoot> without rebuilding headers.
// json-to-dom output:
<table class="table table-striped"><thead>...</tbody></table>
Crossing the Architectural Boundary

The two libraries dock together at a single clean invocation point: window.ks["json-to-dom"].buildSpecElement({ inSpec }). All business calculations, state changes, and theme mappings happen before this line; all DOM attachments happen after.

Clean Architecture

Screaming Architecture & Data Pipeline

Strict separation of concerns between State Stores, Builder Specifications, Native Repainters, and DataProviders.

Read Full Architecture Document
1. Stores Layer

TableStore, FormStore, and DataListStore manage active state, compute multi-tier footer sums and dynamic GST formulas, profile frequency distributions, and enforce top-N limits.

2. Builders & Engine

Pure spec builders (buildTable, buildForm, buildDataList) output pure JSON element trees. The json-to-dom engine instantiates native DOM elements with zero Virtual DOM overhead.

3. Surgical Repainters

Targeted repainters (repaintBody, repaintFoot, refreshTable) update only changed DOM subtrees, preserving input focus, scroll state, and avoiding screen flicker.

How-To Guides

Production-ready, copy-pasteable snippets adhering strictly to the in/local naming convention

import { Table } from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v11/min.js";

const table = new Table({
    inData: [
        { item: "Laptop", category: "Electronics", amount: 1200 },
        { item: "Desk Chair", category: "Furniture", amount: 250 }
    ],
    inColumns: [
        { key: "item", label: "Product Name" },
        { key: "category", label: "Category" },
        { key: "amount", label: "Amount", type: "number", align: "right" }
    ],
    inConfig: {
        serial: true, // Enables '#' serial numbers
        row: { striped: true, hover: true },
        foot: [
            { id: "subTotal", title: "Sub Total", type: "aggregate", values: { amount: "sum" } },
            { id: "tax", title: "Tax (18%)", type: "eval", values: { amount: "subTotal.amount * 0.18" } },
            { id: "grandTotal", title: "Grand Total", type: "eval", values: { amount: "subTotal.amount + tax.amount" } }
        ]
    },
    inTargetContainerId: "table-container"
});

table.render();
import { Form } from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v11/min.js";

const form = new Form({
    inColumns: columns,
    inConfig: {
        body: {
            columns: ["item", "category"] // Fields to generate
        }
    },
    inTargetContainerId: "filter-container"
});

const { treeWithIds, spec, element } = form.render();

// Access pruned tree with element IDs for wiring listeners
const controlsTree = form.getControlsTree();
import { DataList } from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v11/min.js";

const dataList = new DataList({
    inData: data,
    inColumns: columns,
    inConfig: {
        datalist: { columns: ["category", "item"] },
        topN: 10 // Top 10 frequency cap
    },
    inTargetContainerId: "datalist-container"
});

dataList.render();

// Reactively update frequency badges when table filters change:
dataList.update({ inData: table.store.stateData });
import { Table, createDataProvider } 
    from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v11/min.js";

// 1. Create REST CRUD adapter
const dataProvider = createDataProvider({
    inReadUrl: "https://api.example.com/items",
    inCreateUrl: "https://api.example.com/items",
    inUpdateUrl: "https://api.example.com/items/:id",
    inDeleteUrl: "https://api.example.com/items/:id",
    inHeaders: { "Authorization": "Bearer SECURE_TOKEN" }
});

// 2. Supply to Table
const table = new Table({
    inColumns: columns,
    inDataProvider: dataProvider,
    inTargetContainerId: "table-container"
});

// 3. Dynamic async operations
await table.load();
await table.createRecord({ inItem: { item: "New Item", amount: 150 } });
await table.updateRecord({ inId: 12, inItem: { amount: 200 } });
await table.deleteRecord({ inId: 12 });
// Dynamic Theme Switching adhering to in/local convention
export function switchTheme({ inThemeName, inTable, inForm, inDataList }) {
    const localTheme = inThemeName;
    const localTable = inTable;
    const localForm = inForm;
    const localDataList = inDataList;

    // Instantly repaints components with the chosen theme catalog
    localTable.setTheme({ inTheme: localTheme });
    localForm.setTheme({ inTheme: localTheme });
    localDataList.setTheme({ inTheme: localTheme });
}

// Available themes: "default" | "light" | "extraLight" | "dark" | "extraDark"
Avoid Critical Mistakes

How NOT To: Anti-Patterns

Crucial pitfalls, state leaks, and convention violations to steer clear of

Read Full How-Not-To Guide
❌ DON'T: Positional & Unprefixed Params

Passing positional parameters or directly modifying function arguments:

// BAD: Positional arguments & ambiguous origin
function filterData(data, query) {
    // Dangerous: Modifies input array
    return data.filter(d => d.item === query);
}
filterData(items, "ROPE");
✅ DO: Single Object with in / local Mapping

Destructure named in* inputs and map to local* variables immediately:

// GOOD: Explicit, immutable, self-documenting
function filterData({ inData = [], inQuery = "" } = {}) {
    const localData = inData;
    const localQuery = inQuery;
    return localData.filter(d => d.item === localQuery);
}
filterData({ inData: items, inQuery: "ROPE" });
❌ DON'T: Call table.render() on State Filter

Calling .render() destroys the existing table DOM and breaks active input focus:

// BAD: Destroys table DOM and causes flicker
button.addEventListener("click", () => {
    table.store.stateData = filteredRows;
    table.render(); // Heavy full re-parse
});
✅ DO: Use Surgical table.filterStateData()

Use built-in surgical repainters which update only `tbody` and `tfoot` in place:

// GOOD: Fast surgical update without DOM loss
button.addEventListener("click", () => {
    table.filterStateData({ inQuery: { category: "ROPE" } });
});
❌ DON'T: Scatter Raw fetch() Calls in UI

Hardcoding API endpoints and JWT tokens inside DOM button handlers:

// BAD: Tight network & auth coupling in UI
button.onclick = async () => {
    await fetch("https://api.com/items/42", {
        headers: { "Authorization": "Bearer ..." }
    });
};
✅ DO: Abstract Endpoints via createDataProvider

Encapsulate endpoints, authentication, and `:id` substitutions cleanly:

// GOOD: Decoupled CRUD repository adapter
const provider = createDataProvider({ inDeleteUrl: "..." });
const table = new Table({ inDataProvider: provider });
await table.deleteRecord({ inId: 42 });

Components & Providers

Full API reference for Table, Form, DataList, and createDataProvider

Full API Documentation
Table
Class

Renders tables with dynamic serials, sortable columns, and multi-tier summary footers.

Key Methods:
  • .render()
  • .repaintBody()
  • .repaintFoot()
  • .refreshTable()
  • .filterStateData()
  • .setTheme({ inTheme })
  • .load({ inQuery })
Form
Class

Constructs filter/input forms matching schema with control-tree tracking.

Key Methods:
  • .render()
  • .getControlsTree()
  • .setTheme({ inTheme })
DataList
Class

Profiles column values, computes value frequencies, and generates native HTML5 <datalist>.

Key Methods:
  • .render()
  • .update({ inData })
  • .setTheme({ inTheme })
createDataProvider
v12 Factory

Decoupled CRUD repository adapter handling URLs, auth headers, and path params.

Key Methods:
  • .read({ inQuery })
  • .create({ inItem })
  • .update({ inId, inItem })
  • .delete({ inId })
Zero Build Step

CDN & Quick Start

Integrate directly into any web application via jsDelivr CDN without Node.js, bundlers, or build steps.

1. Include Dependencies

Include Bootstrap 5 and the json-to-dom engine:

<!-- Bootstrap 5 CSS -->
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">

<!-- json-to-dom CDN engine -->
<script type="module" src="https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom/docs/dist/v3/min.js"></script>
2. Import Renderers via ESM (v12) 
// Import Table, Form, DataList, and createDataProvider
import { Table, Form, DataList, createDataProvider } 
    from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v12/min.js";

<script type="module">
  import { Table, Form, DataList } 
      from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v12/min.js";

  const columns = [
      { key: "name", label: "Item" }, 
      { key: "qty", label: "Quantity", type: "number", align: "right" }
  ];
  const data = [
      { name: "Apples", qty: 10 }, 
      { name: "Oranges", qty: 25 }
  ];

  // 1. Table
  const table = new Table({ inData: data, inColumns: columns, inTargetContainerId: "table-box" });
  table.render();

  // 2. Form Filter
  const form = new Form({ inColumns: columns, inTargetContainerId: "filter-box" });
  form.render();

  // 3. Autocomplete DataList
  const dataList = new DataList({ inData: data, inColumns: columns, inTargetContainerId: "datalist-box" });
  dataList.render();
</script>
